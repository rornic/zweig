## Migrate background jobs from in-process scheduler to queue-based worker

### Summary

Our background jobs currently run in-process inside the monolith via a cron-style scheduler. This couples job execution to web request capacity, causes noisy-neighbor issues (a slow job can starve request handling), and gives us no retry, backoff, or visibility into failures beyond application logs. This PR migrates job execution to a dedicated queue-backed worker.

### Changes

- Introduced a message queue (`<queue tech, e.g. Redis/SQS>`) as the job broker, decoupled from the request/response path.
- Added a standalone worker process/service that pulls jobs off the queue and executes them, deployed and scaled independently from the web tier.
- Replaced direct scheduler invocations (`scheduler.register(...)`) with job enqueue calls (`queue.enqueue(JobClass, args)`); job classes retain their existing business logic, only the trigger mechanism changed.
- Added per-job retry policy with exponential backoff and a dead-letter queue for jobs that exhaust retries.
- Added structured logging/metrics per job execution (duration, success/failure, retry count) for observability.
- Recurring/cron-style jobs are now scheduled via a lightweight enqueuer (still in-process) that just pushes onto the queue on a schedule, rather than executing the job body itself.

### Why

- **Isolation**: worker crashes or resource spikes no longer affect web request latency.
- **Scalability**: worker count can scale independently based on queue depth.
- **Reliability**: built-in retries and DLQ replace ad-hoc try/catch handling previously scattered across jobs.
- **Visibility**: queue depth and per-job metrics give us actionable alerting that we didn't have before.

### Rollout plan

- Deployed behind a feature flag per job type, allowing incremental cutover rather than a big-bang switch.
- Old in-process scheduler remains as fallback until all job types are verified on the new path, then will be removed in a follow-up PR.

### Testing

- Unit tests for enqueue/dequeue and retry/backoff logic.
- Staging soak test running full job suite through the worker for 48h, comparing output/side effects against the old scheduler.
- Verified DLQ and alerting fire correctly on a forced failure.

### Follow-ups

- Remove legacy in-process scheduler once all jobs are cut over.
- Add per-job concurrency limits.
