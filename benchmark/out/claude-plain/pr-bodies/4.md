## Bump `winston` from v2.4.7 to v3.11.0

### Summary
Upgrades our logging dependency from Winston 2.x to 3.x to pick up maintained security patches, better TypeScript types, and stream-based transports. Winston 2 has been unmaintained for years and is flagged in our dependency audit.

### Breaking change: format configuration API

Winston 3 replaced the string/object-based formatting options with the composable `winston.format` API. Our previous logger config:

```js
const logger = new winston.Logger({
  transports: [
    new winston.transports.Console({
      timestamp: true,
      colorize: true,
      json: false,
    }),
  ],
});
```

no longer works — `winston.Logger` was removed in favor of `winston.createLogger`, and the `timestamp`/`colorize`/`json` boolean flags on transports were dropped entirely. They're now expressed as combinable format functions passed to the logger itself:

```js
const logger = winston.createLogger({
  format: winston.format.combine(
    winston.format.timestamp(),
    winston.format.colorize(),
    winston.format.simple()
  ),
  transports: [new winston.transports.Console()],
});
```

I migrated `src/logging/logger.js` accordingly and updated the two other call sites that were instantiating `new winston.Logger(...)` directly for scoped child loggers (`src/workers/logger.js`, `src/jobs/logger.js`) to use `logger.child({...})` instead, since the old `.child` signature also changed slightly (no longer accepts a `level` override in the options object — that's now inherited from the parent).

### Other changes
- Updated `package.json` / lockfile to `winston@3.11.0`.
- No other transports (file, HTTP) were affected since we only use Console in this repo.

### Testing
- Ran the full test suite; updated two snapshot tests that asserted on raw log output format (timestamp position moved).
- Manually verified log output locally for both normal and error-level logs, confirming colorization and timestamps still render correctly.
