## Add circuit breaker to `PaymentsClient`

### Problem
`PaymentsClient` calls the downstream payments service with a fixed timeout and no protection against sustained failures. During the outage on 2026-08-15, every in-flight request queued until timeout (30s), exhausting the connection pool and thread capacity within minutes. This caused cascading latency across unrelated endpoints that share the same worker pool, turning a single downstream failure into a full outage on our side.

### Change
Wraps `PaymentsClient` calls in a circuit breaker (using `resilience4j`) with the following behavior:
- **Closed**: requests pass through normally.
- **Open**: after 50% of the last 20 requests fail, the breaker opens and requests fail immediately with `PaymentsUnavailableException` instead of waiting on the network.
- **Half-open**: after a 30s cooldown, a limited number of trial requests are allowed through to probe recovery.

Failure fast-paths are logged and emit a `payments.circuit_breaker.state` metric so we can alert on state transitions instead of only on latency/error spikes.

### Why this approach
- Fail-fast preserves capacity for unrelated requests instead of piling up blocked threads/connections.
- Thresholds (50% failure rate, window of 20, 30s cooldown) mirror what we use for the `InventoryClient` breaker, so behavior is consistent across clients.
- Kept the existing per-request timeout unchanged — the breaker sits around it rather than replacing it, so this is additive and low-risk to roll back (config-flagged via `payments.circuitBreaker.enabled`, defaults to `true`).

### Testing
- Unit tests covering closed → open → half-open → closed transitions.
- Load test replaying the 08-15 timeout pattern against a stubbed slow endpoint; confirms breaker opens within ~10s and unrelated requests are unaffected.
- Manually verified fallback error surfaces correctly to callers and doesn't retry indefinitely.

### Rollout
Deploying with breaker enabled but thresholds set conservatively; will tighten after a week of production metrics.
