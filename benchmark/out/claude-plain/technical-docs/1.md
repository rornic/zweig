## DNS Resolution, Step by Step

When you type `www.example.com` into a browser, the browser needs an IP address before it can connect to anything — DNS (Domain Name System) is the internet's phonebook that maps human-readable names to IP addresses.

**1. Browser cache check.** The browser first checks its own cache for a recent lookup of that domain. If found and not expired (respecting the record's TTL), it's used immediately — no network involved.

**2. OS cache check.** If the browser doesn't have it, it asks the operating system, which has its own resolver cache (and checks the local `hosts` file).

**3. Recursive resolver.** If still not found, the request goes to a recursive resolver — usually run by your ISP, or a public one like Google (`8.8.8.8`) or Cloudflare (`1.1.1.1`) if configured. This resolver does the legwork of finding the answer on your behalf, checking its own cache first.

**4. Root nameserver.** If the resolver has no cached answer, it asks a root nameserver, one of 13 logical root server clusters worldwide. The root server doesn't know the IP for `example.com`, but it knows which server handles `.com` domains, so it points the resolver there.

**5. TLD nameserver.** The resolver queries the `.com` top-level domain (TLD) nameserver. This server doesn't know the exact IP either, but it knows which nameserver is authoritative for `example.com`, so it returns that referral.

**6. Authoritative nameserver.** The resolver queries `example.com`'s authoritative nameserver — the source of truth for that domain, typically managed by the domain owner or their DNS host (e.g., Route 53, Cloudflare). This server returns the actual IP address (an A record for IPv4 or AAAA for IPv6).

**7. Response and caching.** The recursive resolver sends the IP back to the OS, which passes it to the browser. The resolver, OS, and browser all cache the result for the duration of the record's TTL, so future lookups skip straight to step 1 or 2.

**8. Connection.** With the IP in hand, the browser opens a TCP connection (and TLS handshake, for HTTPS) to that address and begins requesting the page.

### A few things worth knowing
- This full "root → TLD → authoritative" chain (steps 4–6) is called a **recursive query** from the client's perspective and involves several **iterative queries** made by the resolver.
- In practice, root and TLD lookups are rarely done from scratch — resolvers cache those referrals too, so most real-world lookups are faster than this suggests.
- DNS runs primarily over UDP port 53 (falling back to TCP for larger responses like DNSSEC-signed records).
- The whole process typically takes anywhere from single-digit milliseconds (cached) to a couple hundred milliseconds (full uncached lookup).
