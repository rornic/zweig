## TLS 1.3 Handshake

**Client Hello:** The client sends supported cipher suites, TLS version, and — critically — a set of **key share** values (its ephemeral Diffie-Hellman public keys) for one or more supported groups (e.g., X25519, secp256r1), guessing which group the server will pick.

**Server Hello:** The server selects a cipher suite and key-share group, returns its own key share, and immediately computes the shared secret via (EC)DHE. From this point, the server derives handshake traffic keys and **encrypts everything else** — certificate, certificate verify, and Finished messages — under those keys.

**Server's remaining messages** (all encrypted): `EncryptedExtensions` (non-security-critical parameters), `Certificate`, `CertificateVerify` (a signature over the transcript proving possession of the private key), and `Finished` (a MAC proving the server completed the handshake correctly).

**Client:** Verifies the certificate and Finished MAC, sends its own `Finished`, and can begin sending application data. If the client is authenticating with a certificate, it sends `Certificate`/`CertificateVerify` too.

Net result: **one round trip (1-RTT)** to full encrypted application data, versus two round trips in TLS 1.2.

## Key changes from TLS 1.2

1. **1-RTT instead of 2-RTT.** TLS 1.2 negotiated cipher suite, then separately exchanged key material, then confirmed — a Hello round trip followed by a key-exchange round trip. TLS 1.3 collapses this by having the client guess and send key shares up front.

2. **0-RTT resumption (optional).** For resumed connections, the client can send encrypted application data in its very first flight using a pre-shared key from a prior session — at the cost of losing forward secrecy/replay protection for that early data (it's not idempotency-safe, so servers must guard against replay).

3. **Static RSA and non-ephemeral (EC)DH key exchange removed.** Only (EC)DHE is allowed, so every handshake has forward secrecy — TLS 1.2 permitted RSA key transport, which meant a stolen server private key could decrypt past recorded traffic.

4. **Weak/legacy primitives dropped.** No RC4, DES/3DES, CBC-mode ciphers (avoiding padding-oracle attacks like Lucky13/POODLE), MD5/SHA-1, or compression (removing CRIME-style attacks). Only AEAD ciphers (AES-GCM, ChaCha20-Poly1305) remain.

5. **Far more of the handshake is encrypted.** In TLS 1.2 the certificate exchange was in the clear; TLS 1.3 encrypts everything after ServerHello, reducing metadata leakage and shrinking the attack surface for manipulation.

6. **Renegotiation removed**, replaced by a simpler post-handshake key-update mechanism.

7. **Explicit downgrade protection** via special values embedded in the ServerHello random field, defending against forced-downgrade attacks to TLS 1.2/1.1.

Overall, TLS 1.3 is faster (fewer round trips), simpler (fewer negotiable options and legacy algorithms), and more secure by default (mandatory forward secrecy, AEAD-only, encrypted handshake metadata).
