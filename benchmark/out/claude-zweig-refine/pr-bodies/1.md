fix: eliminate race condition in integration test setup

## Summary

The `OrderProcessing` integration test suite failed intermittently in CI (about 1 in 15 runs) with connection-refused timeouts. Its `beforeAll` ran `startMockPaymentGateway()` and `seedTestDatabase()` in parallel via `Promise.all`, but `seedTestDatabase()` needs the gateway's port to configure webhook URLs. When the database call resolved first, it seeded a webhook pointing at port `undefined`, and every test that hit that webhook hung until timeout.

`startMockPaymentGateway()` usually resolves within milliseconds, so the race stayed hidden until a busier CI runner flipped the ordering often enough to fail the suite.

- `seedTestDatabase()` now awaits `startMockPaymentGateway()` and takes its port directly, instead of both running under `Promise.all`.
- Added an assertion in `seedTestDatabase()` that the port argument is defined, so a future reordering fails immediately with a clear error instead of hanging.
- Removed the 30s timeout bump added in a previous commit as a workaround. It masked the race rather than fixing it.
