TLS 1.3's handshake establishes a shared key in one round trip instead of two, and removes cryptographic options that had caused real vulnerabilities in 1.2.

**The 1.3 handshake**

1. **ClientHello.** The client sends supported cipher suites, a list of key-exchange groups (e.g. X25519, secp256r1), and, crucially, its own key share for the group(s) it's guessing the server will pick.
2. **ServerHello.** The server picks a cipher suite and group, returns its own key share, and immediately derives the shared secret via (EC)DHE. From this point every subsequent message, including the rest of the handshake, is encrypted.
3. **EncryptedExtensions, Certificate, CertificateVerify, Finished.** The server sends its certificate and a signature over the handshake transcript to prove possession of the private key, then a Finished MAC. All of this travels encrypted, unlike in 1.2.
4. **Client Finished.** The client verifies the certificate and signature, sends its own Finished MAC, and application data can flow immediately after.

Because the client sends a key share speculatively in its first message, the server can compute the shared secret without a round trip dedicated to key agreement. That's the 1-RTT handshake. With **0-RTT resumption**, a returning client can send application data alongside its first message, using a pre-shared key from an earlier session, at the cost of losing forward secrecy and replay protection for that first flight.

**What changed from 1.2**

- **One round trip instead of two.** TLS 1.2 negotiated the cipher suite, then exchanged key material, then confirmed, typically 2-RTT before application data. TLS 1.3 collapses negotiation and key exchange into the first exchange.
- **No more RSA key exchange.** Every 1.3 handshake uses (EC)DHE, so every session gets forward secrecy. In 1.2, RSA key exchange was still allowed and offered none.
- **Weak primitives removed.** No RC4, no CBC-mode ciphers, no SHA-1 or MD5 in the handshake, no static Diffie-Hellman, no arbitrary custom DH groups. This closes off attacks like BEAST, Lucky 13, and Logjam that targeted 1.2's cipher flexibility.
- **Renegotiation removed.** 1.2 allowed mid-session renegotiation, the source of a well-known MITM vulnerability (CVE-2009-3555). 1.3 has no renegotiation.
- **Compression removed.** Eliminates the CRIME/BREACH class of attacks.
- **Handshake encrypted earlier.** In 1.2, the certificate and most handshake messages were sent in cleartext. In 1.3, everything after ServerHello is encrypted, which also hides more metadata from passive observers.
- **Downgrade protection.** The server embeds a special value in its random field if it detects a downgrade attempt, letting clients detect deliberate version rollback.

Net effect: fewer round trips, a much smaller and audited set of cryptographic primitives, and forward secrecy guaranteed on every connection rather than optional.
