fix: eliminate race condition in integration test setup

## Summary

The `OrderProcessing` integration test suite failed intermittently in CI (roughly 1 in 15 runs), timing out with connection-refused errors. Two setup calls in `beforeAll`, `startMockPaymentGateway()` and `seedTestDatabase()`, ran in parallel via `Promise.all`, but `seedTestDatabase()` reads a port number from `startMockPaymentGateway()`'s return value to configure webhook URLs. When the database call resolved first, it seeded a webhook pointing at port `undefined`, and later tests calling that webhook hung until timeout.

The race only surfaced under load, since `startMockPaymentGateway()` normally resolves within a few milliseconds. On a busier CI runner, the ordering flipped often enough to fail the suite regularly.

- Sequenced the two calls: `seedTestDatabase()` now awaits `startMockPaymentGateway()` and receives its port directly, instead of both running under `Promise.all`.
- Added an assertion in `seedTestDatabase()` that the port argument is defined, so a future reordering fails immediately with a clear error instead of hanging.
- Removed the 30s timeout bump added in a previous commit as a workaround. It masked the race rather than fixing it.
