## fix: add circuit breaker to downstream service client

Wraps the downstream service client in a circuit breaker so repeated failures trip it open, instead of every caller queuing up behind a slow timeout during an outage.

### Changes

- Add circuit breaker around the client's request path, tuned to trip after a run of consecutive failures within a rolling window.
- Fail fast with a dedicated error when the breaker is open, so callers can distinguish "downstream is down" from a normal request failure.
- Half-open probing after a cooldown period, so the breaker recovers automatically once the downstream service is healthy again, without a manual reset.
- Add metrics/logging on state transitions (closed → open → half-open) for visibility during incidents.

Previously, an outage meant every in-flight request waited out its full timeout before failing, and retries piled more load onto an already-struggling downstream service. Requests now fail in milliseconds once the breaker trips, and load stays off the downstream service until it's back.

### Testing

Unit tests cover the trip threshold, the open-state fast-fail path, and the half-open recovery transition. Manually verified against a stubbed downstream client that simulates timeouts.
